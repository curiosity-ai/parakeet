# CLAUDE.md

Guidance for Claude Code (and other contributors) working in this repository.

## Layout

- `src/Parakeet/` — the library (NuGet package `ParakeetSharp`): audio front end, FastConformer encoder, TDT decoder,
  checkpoint readers (`.nemo`, ONNX export), SIMD numerics.
- `src/Parakeet.Cli/` — the `parakeet` command-line tool (`transcribe`, `bench`).
- `tests/Parakeet.Tests/` — xUnit: kernel tests (always run) and model tests (need the environment below).
- `benchmarks/Parakeet.Benchmarks/` — in-process comparison with ONNX Runtime, GEMM micro-benchmarks.
- `tools/Parakeet.TestAudio/` — regenerates `testdata/audio` with the Voxwerk NuGet packages.
- `scripts/onnx_reference.py` — ONNX Runtime reference dumps for the parity tests.
- `.devops/azure-pipelines.yml` — Azure DevOps CI: build, test, pack `ParakeetSharp` (CalVer `yy.M.<buildId>`), push on `master`.
- `.reference/` — the original Go/ONNX Runtime server, kept read-only as the reference implementation. Its GitHub
  workflows are disabled (`.github/workflows/*.disabled`); do not re-enable them.

## Build and test

```bash
dotnet build Parakeet.slnx -c Release
dotnet test tests/Parakeet.Tests -c Release
```

Model tests need `PARAKEET_MODEL` (a `.nemo` file), `PARAKEET_REFERENCE_DIR` (output of `scripts/onnx_reference.py`) and
optionally `PARAKEET_ONNX_DIR` (the fp32 ONNX export); without them they print `SKIPPED` and pass. Run the suite with
both `parakeet-tdt-0.6b-v2` and `-v3` (and their own reference dumps) after changing numerics.

## Rules

- FP32 results must stay numerically equivalent to ONNX Runtime: the parity tests bound every layer's relative error,
  and every reference clip must decode to identical tokens. Approximations belong behind an option (like
  `WeightPrecision.Int8`), never in the default path.
- Measure performance with `benchmarks/Parakeet.Benchmarks` (interleaved, medians); single runs on a shared machine
  vary by ±15%. `PARAKEET_PROFILE=1` prints a per-stage breakdown in `parakeet bench`.
- The unrolled micro-kernels in `Numerics/Gemm.cs` (`Kernel512R1..12`) and `Numerics/Int8Gemm.cs` (`KernelR1..6`) are
  generated by `scripts/gen_kernels.py`; edit the generator, paste its output, and re-check the JIT output
  (`DOTNET_JitDisasm=<method>`) for register spills.
- Gate commits on a successful build and test run.
